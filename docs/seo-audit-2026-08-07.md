## 一、核心数据发现（24h GSC）

### 1.1 设备分布：移动端是主战场

| 设备 | 点击 | 展示 | CTR | 平均排名 |
|------|------|------|-----|----------|
| 移动设备 | 8 | 593 | **1.35%** | **7.96** |
| 桌面 | 7 | 2,997 | 0.23% | 26.09 |
| 平板 | 0 | 10 | 0% | 5.9 |

**关键洞察**：移动端流量虽然展示量只有桌面的 1/5，但点击占比接近一半，且排名显著更好。所有优化必须优先以移动端体验为准。

### 1.2 Block Out 子站表现

- **查询数**：112 个 Block Out 相关查询 / 总查询 556
- **展示量**：229 次
- **平均排名**：5.99（已经不错）
- **点击量**：仅 2 次（来自查询维度）

**最大问题不是排名，而是点击率（CTR）**。大量关键词排名在 3–8 位，但 CTR 为 0%。

### 1.3 高展示、低 CTR 的机会词（已落地优化）

|------|------|------|-----|
| block out level 209 | 17 | 8.65 | 0% |

### 1.4 URL 信号分裂

GSC 同时收录了两种形态：

- `https://blockout.stratlore.com/en/levels/209/`（规范 URL）
- `https://blockout.stratlore.com/en/levels/209`（无尾斜杠）

两者都在瓜分同一关键词的展示量，导致排名信号分散。

## 二、SERP 截图诊断

### 2.1 搜索结果页特征

从 3 张移动端截图可见：

1. **视频轮播极其醒目**：YouTube 视频常常占据首屏大量空间。
2. **竞争者标题更具体**：blockoutlevel.com / blockout.strategies 等使用 "Step by Step"、"Solution"、"Walkthrough & Guide"。
3. **图片结果出现**：部分查询底部出现棋盘截图网格。
4. **People Also Ask（相关问题）** 出现：例如 "What is block out?"、"How do you play block out?"。
5. **品牌认知弱**：用户更容易点击带有视频缩略图或明确步骤承诺的结果。

### 2.2 我们的 SERP 劣势

- 标题缺少 "Step by Step"、"Solution" 等高点击修饰词。
- 没有 Open Graph / Twitter Card 图片元数据，无法在分享和富媒体结果中脱颖而出。
- 缺少 HowTo 富媒体结构化数据。
- 视频结构化数据缩略图使用低质量 `hqdefault`，而非 `maxresdefault`。

## 三、已落地的代码级修复

### 3.1 修复 hreflang / canonical 尾斜杠冲突（Critical）

**问题**：`buildFullAlternates` 生成的 alternate URL 不带尾斜杠，而 canonical 带尾斜杠，违反 Google 国际 SEO 规范。

**修复**：

- `lib/seo/metadata.ts`：在 `buildFullAlternates` 中对 `rest` 补尾斜杠，确保所有 alternate URL 与 canonical 一致。
- `scripts/prerender.ts`：增加 `normalizeHreflang` 后处理，将 vinext 渲染的 `hrefLang` 统一修正为小写 `hreflang`。

**验证**（L37 静态 HTML）：

```html
<link rel="canonical" href="https://blockout.stratlore.com/en/levels/37/"/>
<link rel="alternate" hreflang="en" href="https://blockout.stratlore.com/en/levels/37/"/>
<link rel="alternate" hreflang="x-default" href="https://blockout.stratlore.com/en/levels/37/"/>
```

### 3.2 301 合并无尾斜杠 URL（Critical）

**问题**：GSC 中 `/209` 与 `/209/` 同时存在，分流排名信号。

**修复**：`worker/index.ts` 在请求进入 vinext handler 前增加 301 跳转：

```ts
if (url.pathname !== "/" && !url.pathname.endsWith("/") && !url.pathname.includes(".")) {
  return new Response(null, { status: 301, headers: { location: target.toString() } });
}
```

**验证**：`/en/levels/14` → 301 → `/en/levels/14/`。

### 3.3 使用 `level.seo.title` 优化标题（High）

**问题**：`generateMetadata` 之前使用 `level.title`（"Block Out Level 37 Walkthrough"），忽略了内容 JSON 中更完整的 `seo.title`。

**修复**：`app/[locale]/levels/[level]/page.tsx` 优先使用 `level.seo.title` / `level.seo.description`。

**效果**：

- 旧标题：`Block Out Level 37 Walkthrough | Block Out! Guides`
- 新标题：`Block Out Level 37 Walkthrough and Solution | Block Out! Guides`

### 3.4 添加 Open Graph 与 Twitter Card（High）

**问题**：此前无任何 og:image、twitter:card 等社交/富媒体元数据。

**修复**：在关卡页 `generateMetadata` 中补充：

- `og:title`、`og:description`、`og:url`、`og:type=article`
- `og:locale`、`og:site_name`
- `og:image` / `twitter:image`：优先使用棋盘图 `/boards/{N}.avif`，无棋盘图时回退到 YouTube `maxresdefault.jpg`
- `twitter:card=summary_large_image`

**验证**（L37）：

```html
<meta property="og:title" content="Block Out Level 37 Walkthrough and Solution"/>
<meta property="og:image" content="https://img.youtube.com/vi/q4TsAQcyxgs/maxresdefault.jpg"/>
<meta name="twitter:card" content="summary_large_image"/>
```

**验证**（L294，有棋盘图）：

```html
<meta property="og:image" content="https://blockout.stratlore.com/boards/294.avif"/>
```

### 3.5 本地化结构化数据 + HowTo + 视频缩略图优化（High）

**问题**：`FAQPage` 结构化数据 hardcoded 英文；`VideoObject` 使用低质量 `hqdefault`；缺少 `HowTo` 富媒体数据。

**修复**：`lib/seo/structured-data.ts`

- FAQ 问题/答案改为走 `messages/*.json` 的本地化键。
- `VideoObject.thumbnailUrl` 改为 `maxresdefault → sddefault → hqdefault` 三级候选。
- 为 `full-guide` 关卡生成 `HowTo` + `HowToStep` 结构化数据，步骤文本取自现有 `steps`。

**验证**（L37）：

```json
{
  "@type": "HowTo",
  "name": "Block Out! Level 37 Walkthrough and Video Solution",
  "step": [{"@type":"HowToStep", "position":1, ...}, ...]
}
```

## 四、仍待推进的优化项（按优先级）

### 4.1 P0：提升移动端 CTR 的标题与描述

**建议**：

- 对 `content/en/levels/*.json` 中的 `seo.title` 批量 A/B 风格优化，加入高点击词：
  - "Block Out Level {N} Solution: Step-by-Step Walkthrough"
  - "How to Beat Block Out Level {N} (Video + Tips)"
- 描述中突出 "step-by-step moves"、"common mistakes"、"verified board" 等差异点。

**注意**：属于内容层改动，需同步遵守"生成即发布"与 10 语言 i18n 规则。

### 4.2 P1：视频封面策略升级

**建议**：

- 自有棋盘图 `/boards/{N}.avif` 已在 OG 中优先使用，继续补齐 1–150 关的棋盘图下载。
- 在 SERP 中，视频缩略图极吸睛；可考虑在页面首屏更突出视频播放器，并争取视频富媒体结果。

### 4.3 P1：攻克 PAA（People Also Ask）

截图中出现了 "What is block out?"、"How do you play block out?" 等 PAA。建议新增/优化编辑型内容：

- `/en/guides/what-is-block-out/`
- `/en/guides/how-to-play-block-out/`
- 在关卡页 FAQ 中增加 "How do I beat hard Block Out levels?" 等常见问题。

### 4.4 P1：内链与话题集群

**建议**：

- 关卡页增加 "Related levels" 模块（利用 `relatedLevelNumbers`）。
- 难度标签链接到 `/en/hard-levels/` 或按难度筛选的关卡库。
- 障碍物/助推器文章链接到相关关卡，形成 topic cluster。

### 4.5 P2：Core Web Vitals 与图片优化

**发现**：静态 HTML 中棋盘图的 preload 仍使用 `/_vinext/image?url=%2Fboards%2F...` 优化端点，即使 `images.unoptimized: true` 已设置。

**建议**：

- 确认生产环境 `/_vinext/image` 是否稳定、缓存是否合理。
- 若端点引入延迟，可考虑对棋盘图使用原生 `<img>` 或强制 `unoptimized` prop。
- 优先 LCP 资源：首屏棋盘图与视频封面应使用 `<link rel="preload" as="image">` 且指向可直接缓存的静态 URL。

### 4.6 P2：内容覆盖率

- L171 永久缺口、L218 禁用需保持现状。
- 继续推进非 EN 语言的关卡本地化 `content/<locale>/levels/*.json`，减少英文回退比例，提升各地区 CTR。
